How it works

Queues are account-aware and folder-based, so it is easy to see what is waiting, posted or failed.

Log in once

Start a login session per platform from the Accounts view. Sessions are saved on disk.

Drop videos in the queue

Place files in the account's pending folder. Supported: mp4, mov, webm, avi, mkv.

Schedule or post

Pick a cron, a daily time or instant mode. Uploads move to posted or failed.

Queue layout 
queue/<account>/tiktok/pending
queue/<account>/instagram/pending
queue/<account>/youtube/pending

Quick start

Requires Node.js 18+, npm, Playwright Chromium, and FFmpeg/ffprobe in your PATH. yt-dlp is optional.

1 · Install 
git clone https://github.com/Katzca/AutoSocial.git
cd AutoSocial
npm ci
npx playwright install chromium
npm run doctor
2 · Configure and run (PowerShell) 
Copy-Item .env.example .env
npm run dashboard
# open http://127.0.0.1:3000

Begin with the Setup view. It checks dependencies and shows where to drop videos for each platform.

Security, local by design

This is built for a local workstation, not as a hosted SaaS app.

Loopback only

The dashboard binds to 127.0.0.1 by default and has no authentication, so keep it local.

Same-origin guard

Mutating requests are checked so random websites can't trigger local actions through your browser.

Remote access is opt-in

Non-local binding is blocked unless DASHBOARD_ALLOW_REMOTE=true is set. Use only on a trusted network.

Responsible use

The goal is a practical creator-operations dashboard, not mass posting or engagement spam. You are responsible for how you use it:

  • Follow each platform's terms, account policies and rate limits, and respect local law.
  • Only post or download content you own or have permission to use.
  • Prefer official platform APIs where they fit your workflow.
  • Avoid spam, deceptive behavior and unauthorized scraping.
  • Keep sessions local and rotate credentials if they are ever exposed.
